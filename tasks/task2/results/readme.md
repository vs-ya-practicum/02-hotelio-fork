# Стратегия миграции данных Task 2

Перед переключением записи бронирований нужно перенести данные из таблицы `booking` монолита в таблицу `bookings` `booking-service` и синхронизировать последовательность идентификаторов. Из этих же данных нужно заполнить `booking_history`.

## To-Be

`booking-service` самостоятельно хранит и изменяет данные бронирований. Монолит временно перенаправляет создание бронирований в `booking-service`; получение списка остаётся в монолите до отдельной миграции. `booking-history-service` асинхронно получает события `BookingCreated` из Kafka и сохраняет их идемпотентно по `booking_id`.
